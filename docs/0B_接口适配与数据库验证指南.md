## 1. 本阶段完成了什么

本批先把“外部服务是否可靠可调用、结果能否被程序正确消费、数据库能否安全保存业务数据”打通。接口调用与业务逻辑分离，后续解析和入库流程复用这些适配器，不在路由中直接拼请求。现有数据基线不变，旧`rag-diagnosis-agent`未修改，未读取其密钥或借用其数据库。

| 模块 | 当前实现 | 主要代码 |
| --- | --- | --- |
| 独立数据库 | 专用库/角色初始化；版本化SQL迁移；只读连接检查 | `scripts/bootstrap_database.sql`、`infrastructure/database.py` |
| 业务建模 | 文档、原文版本、解析元素、入库任务四类表及外键/唯一约束 | `infrastructure/migrations/001_ingestion.sql` |
| 模型接口 | 对话、视觉、Embedding、Rerank的独立适配与响应校验 | `infrastructure/model_adapters.py` |
| 解析接口 | MinerU提交、上传、查询、结果包校验；中断后凭任务编号续查 | `infrastructure/parser_adapter.py` |
| 调用边界 | 显式预算、限时、有限GET重试、大小限制、脱敏调用记录 | `infrastructure/http_gateway.py` |
| 操作入口 | 独立数据库/服务检查命令；固定公开样例；JSON结果报告 | `cli.py`、`application/service_checks.py` |

以上Python路径均相对于`backend/src/multimodal_rag/`。当前仍只提供API调试页，不是最终问答前端；`/health/ready`继续返回503，不能将“配置已填”误报为“业务已就绪”。

## 2. 存储选型保持怎样的分工

**PostgreSQL是业务事实的权威存储，Chroma和BM25是可重建的检索索引。** PostgreSQL保存文档、版本、元素和任务，后续再增加Chunk、会话及引用；Chroma保存向量、检索文本副本和必要标识；bm25s将关键词索引写入磁盘，启动时加载，不重新分词建库。原文、图片和解析产物保存在受控文件目录。不能把业务状态都塞进Chroma，也不因为使用BM25就必须引入Elasticsearch。

这适合当前模块化单体、单worker的规模。需要分布式检索、复杂过滤或多副本时再评估ES/OpenSearch。后续先构建不可变的Dense/BM25同版本产物，检查完整性后在PostgreSQL切换活动版本指针；不是宣称三个存储拥有跨系统事务。**0B仅实现PostgreSQL基础迁移，Chroma、bm25s及索引发布尚未接通。**

当前表的关系是：一份文档有多个原文版本，一个版本关联多个解析元素和处理任务。版本保存原文SHA256；元素保存顺序、标题路径和来源定位JSON；任务保存幂等键、处理配置及远端任务编号。迁移使用文件校验和，已执行SQL被修改时拒绝继续；新增变更应增加下一份迁移文件。

## 3. 数据库需要你在本机完成的配置

本机已安装PostgreSQL16，不需要再安装新的数据库软件。这里新建独立的`multimodal_rag`库和`multimodal_rag_app`账号，**不使用旧项目的`rag_diagnosis`**。管理员口令只在本机提示中输入。

```powershell
# 在项目根目录执行
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres -f scripts/bootstrap_database.sql
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres
```

进入`psql`后设置新账号的口令，再退出：

```text
\password multimodal_rag_app
\q
```

只在不存在`.env`时复制模板，避免覆盖后续已经填写的凭证：

```powershell
if (-not (Test-Path -LiteralPath '.env')) { Copy-Item -LiteralPath '.env.example' -Destination '.env' }
notepad .env
```

将下列内容填写在**文件中，不是PowerShell命令行**；不要把真实口令发到聊天中：

```ini
MRAG_POSTGRES_DSN="host=127.0.0.1 port=5432 dbname=multimodal_rag user=multimodal_rag_app password=在本机填写"
MRAG_BAILIAN_WORKSPACE_ID=在本机填写北京工作空间编号
MRAG_BAILIAN_API_KEY=在本机填写百炼密钥
MRAG_PARSER_API_KEY=在本机填写MinerU令牌
MRAG_MODE=offline
MRAG_API_ENABLED=false
```

口令如含空格或连接串特殊符号，需要按libpq连接串规则转义。Parser令牌未申请时可先留空；它不是百炼密钥。四个模型服务的单独密钥可以留空，统一回退到`MRAG_BAILIAN_API_KEY`。配置检查只显示是否配置，不输出秘密值。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-env
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli db-check
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli db-migrate --confirm
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli db-check
```

迁移前检查可以显示“已连接、尚无迁移”；迁移后应出现`001_ingestion.sql`。数据库操作不要求开启外部API。程序仅允许本机指定数据库与账号，健康检查/启动不会自动建表。

## 4. 模型与解析接口怎样验证

| 服务 | 当前配置基线 | 程序检查重点 |
| --- | --- | --- |
| 对话 | `qwen-plus` | 非空文本、正常结束标记、实际用量字段 |
| 图像理解 | `qwen3-vl-plus` | 确实发送原图字节，不只发送文件名；结果非空 |
| 文本向量 | `text-embedding-v4`，1024维 | 返回数量、索引对应、维度、有限非零数值 |
| 重排 | `qwen3-rerank` | 候选编号不重复/不越界，分数有效且按序 |
| 文档解析 | MinerU API v4，`vlm` | 提交编号、任务状态、Markdown/结构JSON/图片引用完整性 |

百炼四项共用密钥不代表请求路径相同：对话/视觉/Embedding使用北京工作空间的`compatible-mode/v1`，当前Qwen重排使用`compatible-api/v1/reranks`。代码分别处理，不强行把所有服务当作聊天接口。模型名称与账号权限仍需要真实验证，不能以Mock成功代替。参考：[百炼Embedding](https://help.aliyun.com/zh/model-studio/embedding)、[百炼重排](https://help.aliyun.com/zh/model-studio/text-rerank-api)、[MinerU官方API](https://mineru.net/doc/docs/index_en/)。

确认本批预算并填写凭证后，将`.env`中的`MRAG_MODE`改为`api`、`MRAG_API_ENABLED`改为`true`。每次检查还必须显式加`--confirm-live`和`--max-requests`。建议模型每项只请求一次：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-service --service chat --confirm-live --max-requests 1
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-service --service vision --confirm-live --max-requests 1
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-service --service embedding --confirm-live --max-requests 1
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-service --service rerank --confirm-live --max-requests 1
```

视觉样例取自已有开发集图像，不上传个人文件；0B解析验证仅提交MinerU官方公开样例的前两页。解析先提交一次，报告立即保存任务编号；后续使用该编号查询，避免重复提交：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-service --service parser --confirm-live --max-requests 1
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-service --service parser --task-id 报告中的任务编号 --confirm-live --max-requests 3
```

查询未完成时退出码3、状态`pending`，不是失败，也不能记成通过；完成并检查结果包后才是`validated`。GET的有限重试同样消耗调用预算；POST/PUT失败不自动重发。签名上传/下载地址只允许明确域名，且不转发API令牌。若供应商返回新域名，应先核对来源再更新白名单，不放开任意地址。

报告位于`evals/results/service-checks/`，记录次数、耗时、状态、模型及供应商实际返回的用量。缺失用量或费用记为`null`，不填虚假的零费用；不写密钥、完整响应、原始提示词或签名URL。**这是接口连通与结构验证，不是回答准确率或OCR质量评测。**
