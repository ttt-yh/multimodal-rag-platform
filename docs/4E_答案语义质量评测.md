# 阶段4E：答案语义质量评测

## 目标与边界

阶段4D验证了标准证据是否被答案实际引用，但“引用正确”不代表“答案理解正确”。本阶段不重新生成答案，而是读取已保存的8条可回答题结果，从必要要点、事实正确性、信息完整性和证据一致性四个角度进行评分。参考答案和Gold证据只进入评分端，没有泄露给被测RAG链路。

## 评测方法

第一层采用确定性必要术语组。例如TLS题检查`false`、`cluster`、`skip-verify`、`preferred`等关键取值是否出现；该方法可稳定发现关键参数遗漏，但不能判断语义关系是否正确。第二层使用Qwen-Plus作为LLM Judge，结合问题、参考答案、候选答案及模型实际引用的证据，对正确性、完整性和证据一致性分别按0～4分评分。评分结果经过严格JSON契约校验，低于3分、出现严重错误、必要术语覆盖不足或数据本身存在歧义时进入人工复核队列。

由于候选答案和评判都使用Qwen-Plus，存在同模型自评偏高的风险。本阶段结果标记为`development_llm_judge_pending_human_review`，不能包装成人工审核后的正式答案正确率。

## 数据问题与处理

两条题曾进入人工复核：`table-concurrency`题询问默认值，但参考答案没有数值；Region Merge题没有说明“默认值”具体指哪个参数。修订问题已对照原文行号核验，保留结构化`question_revision`记录并发布到文本Gold；参考答案与证据Chunk没有变化。需要继续保留的边界是：人工审核针对问题修订，而不是对全部8条生成答案逐条人工评分，因此整体评级仍为开发级LLM评测。

完整汇总位于`evals/results/stage4/semantic_eval_summary.json`，逐题理由和缺失项位于`evals/results/stage4-semantic/<index_version_id>/`。网页评测页同时展示确定性要点覆盖、LLM完整性和人工复核数量，避免只展示一个容易误解的综合高分。
