# 阶段3A：扩展文本基线准备

## 本阶段目标

在不修改当前激活索引、不消耗模型 API 额度的前提下，准备下一轮更接近真实规模的文本 RAG 基线。输入仍限定为中文 Markdown，先验证多文档入库和检索评测，再进入 PDF/图片处理与 Agentic RAG。

## 已生成产物

- `data/manifests/ingestion_chinese_md_stage3.jsonl`：从 1,109 份中文 Markdown 中确定性选取 40 份，覆盖部署、配置、性能、监控、存储、事务和故障排查等 24 个目录。
- `evals/datasets/retrieval_stage3_candidates.jsonl`：从已有 180 条中文问答候选中筛出 19 条与这 40 份文档相关的候选，其中 16 条可回答、2 条明确无答案、1 条待澄清。
- `evals/results/stage3/text_subset_summary.json`：记录来源数量、选中文档哈希、目录分布和候选规模。
- `evals/results/stage3/chunk_estimate.json`：按当前结构感知切分参数完成的离线 Chunk 数量估算。

这些候选的证据仍以原文 Section ID 表示，`review_status=pending_index_mapping`、`gold_eligible=false`。新索引生成 Chunk 后，必须将 Section 证据映射到实际 Chunk，并由人工确认后才能纳入正式指标。

## 选择规则

脚本 `scripts/prepare_stage3_text_subset.py` 只读取既有 manifest，按主题关键词打分并按目录轮询，保证结果可复现且避免单一目录占满样本。脚本不会访问模型、写入 PostgreSQL、修改 Chroma/BM25 或改变 active index。

## 下一步

1. 检查 40 份原文是否均能从白名单路径读取，并运行 `scripts/estimate_stage3_chunks.py` 查看切分后的 Chunk 数量。
2. 用户确认本批 Embedding/Rerank 调用预算后，使用该 manifest 执行独立的文本入库任务。
3. 审核 19 条候选并把原文 Section 映射到新 Chunk，形成第二版正式评测集。
4. 在同一索引和同一评测集上对比 Dense、BM25、RRF 与 Rerank。
