# 数据集准备与使用指南

本阶段已准备完整原始语料、官方标注、项目划分和独立的中文工程回归资料。不是仅下载小样本；后续可以按成本分批执行解析和模型评测，但不需要再为本版范围补下载主语料。所有资料位于新工程，未更改旧 `rag-diagnosis-agent`。

中文补齐后，以 **TiDB 中文技术文档为产品主场景**，英文教材为独立公开基准。新增数据的来源、证据、审核状态和复现方法见[中文主语料补齐说明](中文主语料补齐说明.md)。本指南原有英文基准的规模与划分不变。

英文独立基准为《Introduction to Computer Science》（945 页）和《Introduction to Python Programming》（415 页），包含正文、代码、表格、图片和示意图。其官方查询含英语、法语、西班牙语、意大利语、德语、葡萄牙语，不含中文；中文端到端问答使用单独准备的 TiDB 候选，不混算语言效果。

解析集包含简体中文 765 页、英文 755 页、中英混合 116 页、繁体中文 13 页及其他语言 2 页。官方元素包括 665 个表格、1385 个 figure、2066 个独立公式等；元素数量不等于独立问题数量。它支持中文解析验证，不等于已经具备中文真实文档的端到端问答基准。

中文模拟资料为本项目通过确定性模板自动构建的虚构规格，没有使用公司数据或调用模型。题目、答案和事实可对应检查，但模板化程度较高，只用于回归测试，不包装为真实企业样本或复杂推理基准。

## 2. 应该从哪里开始看

1. `evals/results/data-readiness/report.html`：直接用浏览器打开，查看数量、验收结果与警告。
2. `data/raw/tidb_zh/source/`：中文主原文及图片；`output/pdf/`：322 页同源专题册；`data/raw/vidore/pdfs/`：两本英文基准 PDF。
3. `data/splits/vidore/dev_english.jsonl`：正式开发时使用的问题与证据。
4. `data/derived/engineering/documents/`：易读的中文模拟规范。
5. `evals/cases/agent_workflows.jsonl`：未来 Agent 应如何行动的测试契约，当前尚未执行。

为了保护验收集，日常开发先看 `dev`；`test` 留到阶段验收。这里的“锁定”是版本与流程约定，不是数据库访问控制。

**不允许递归扫描整个 `data/` 文件夹直接入库。** 后续数据导入只读取相应白名单：

| 白名单 | 允许作为输入的内容 | 应使用的范围 |
| --- | --- | --- |
| `ingestion_chinese_md.jsonl` | 1,109 份中文 MD 及其图片引用 | 默认主知识库 `tidb_zh_85`；不用评测参考文档编号作检索过滤 |
| `chinese_pdf_variants.jsonl` / `chinese_txt_variants.jsonl` | 同源格式替换清单 | 不与对应 MD 重复入库；PDF 必须按每篇源文的页范围处理 |
| `ingestion_public.jsonl` | 两本原始 PDF | 独立英文知识库 `vidore_cs` |
| `ingestion_engineering.jsonl` | 24 份 MD/TXT | 独立模拟库 `engineering_fictional` |

参考答案、问题、相关性标注和官方预解析 Markdown 不能进入正式索引。`upstream_ocr_reference.jsonl` 是官方机器 OCR 对照，不是人工金标准，也不能代替我们将要开发的解析链路。

## 4. 页码、证据与标注如何关联

`data/annotations/vidore/pages.jsonl` 保存官方 `corpus_id`、稳定 `page_id`、原始 PDF、零起始 `page_index`、一起始 `page_number`、章节、图像尺寸及哈希。不要使用 Parquet 行号当作 PDF 页码；官方页面排列并非按物理页码顺序。

例如 `page_index=110` 表示 PDF 第 111 页。书内印刷页码可能为 101，界面引用应先以 PDF 物理页码为准。`page_id` 对应官方相关性记录，后续 Chunk 只需回指原始证据即可沿用评测集。

问答中保留官方问题类型、内容模态、参考答案、原始人工答案、生成来源和相关页面。官方 `answer` 是对人工标注答案的模型合并版本；本项目没有把它重新标记成逐条人工审核答案。相关性得分 2 表示页面可完整回答，1 表示包含关键事实但可能仍需其他页；不能把两种含义混淆。

区域同时保存原始像素坐标与规范化坐标。ViDoRe 的 6294 条相关性记录均能定位到已下载页面，现有区域坐标均通过边界检查。边界检查只证明坐标合法，不能证明标注语义一定正确。

## 5. 为什么开发集与测试集不是原计划的 6:4

首先根据同一原始答案识别翻译组，并校验各组的六种语言、相关页及相关性得分一致，最终得到 215 组。随后将共享证据页面的问题连成组，发现其中 **182 题组成一个大型连通组**。该组作为开发集，其余 33 题作为锁定测试集；多语言版本随原始问题一起划分。

| 划分 | 原始英文问题 | 包含六种语言的条目 |
| --- | --- | --- |
| 开发 | 182 | 1092 |
| 测试 | 33 | 198 |
| 全部 | 215 | 1290 |

此划分保证翻译组和标注证据页不重叠，但两侧仍共享 17 个章节。若进一步要求所有关联章节隔离，分组规模会变为 214 和 1，无法获得有意义的章节独立开发/验收。因此本版明确采用页级隔离，不声称章节独立或文档独立泛化，也不以随机拆分凑出 6:4。

测试题数量较少，后续报告应给出样本量与逐题结果，不将比例的小幅波动解释为稳定提升。全部 215 题可用于固定官方基准对照，但开发后不能把全量成绩称作完全未见的测试成绩。

OmniDocBench 按可识别的来源文件名分组后固定哈希划分：开发 996 页，测试 655 页。含 UUID 的页面不一定能恢复原文档归属，因此这也不是严格文档独立拆分；完整原始数据和官方 subset 字段保留，可运行官方全量解析基准。

## 6. 已完成的检查与限制

自动验收入口为 `scripts/audit_datasets.py`，输出 HTML、JSON、JUnit 和完整日志。检查涵盖：完整下载清单与上游哈希、PDF 页码全覆盖、图片文件关联、问答与证据引用、翻译与证据页隔离、答案不进入入库白名单、模拟事实与原文一致，以及 Agent 案例不被标记为已执行。

另外对两本 PDF 各渲染了一页，抽查图文和表格可读性，并查看了官方页图和一页中文手写解析样本。**这是可读性抽查，不是对全部 3011 页或全部答案完成了人工审核。**

必须保留的限制：

- OmniDocBench 存在 **54 条越界多边形标注，涉及 26 页**。清单在 `coordinate_warnings.json`。原值未改写；后续针对这些区域复核定位指标，不能无提示裁剪标注或剔除整页。
- **12 张图片超过 5000 万像素**，其中一张约 1.45 亿像素。清单在 `large_images.json`。原图保留；正式解码、上传前需设置像素预算，缩放必须保存坐标变换关系。数据准备使用图像格式校验，没有对所有超大图做全尺寸解码。
- 部分上游文件名本身含异常字符，原始文件名与记录原样保留，不因终端显示异常就擅自重命名。
- 官方问题/答案仍可能不完整，未标注页面不一定就是错误证据；争议样例需保留人工复核通道。
- 当前共 80 条 Agent 案例及 8 条生命周期案例，均为待执行契约；部分依赖后续框架注入超时、空检索或缺失图片。当前没有 Agent 成功率。
- 当前没有测量 Recall、nDCG、回答正确率或模型费用。数据检查通过率不能作为系统效果成绩。

## 8. 如何重新准备与验收

从工程目录执行，以下命令不需要数据库或模型密钥。需要 Python 3.12、uv 和网络访问：

```powershell
uv venv --python 3.12 --cache-dir .uv-cache .venv-data
uv pip install --python .venv-data/Scripts/python.exe --cache-dir .uv-cache -r requirements-data.lock.txt
.venv-data/Scripts/python.exe scripts/download_datasets.py --workers 8
.venv-data/Scripts/python.exe scripts/build_engineering_fixtures.py
.venv-data/Scripts/python.exe scripts/prepare_datasets.py
.venv-data/Scripts/python.exe scripts/download_chinese.py
.venv-data/Scripts/python.exe scripts/prepare_chinese.py
.venv-data/Scripts/python.exe scripts/download_chinese_assets.py
.venv-data/Scripts/python.exe scripts/prepare_chinese.py
.venv-data/Scripts/python.exe scripts/build_chinese_cases.py
.venv-data/Scripts/python.exe scripts/build_chinese_documents.py
.venv-data/Scripts/python.exe scripts/package_chinese_review.py
.venv-data/Scripts/python.exe scripts/audit_datasets.py
```

每条命令成功后再执行下一条。下载器支持断点续传与已有文件哈希校验，锁定版本不会跟随 `main` 静默变化。规范化脚本会重建本工程的派生页图、标准标注和固定划分，不能手工修改这些生成文件作为长期标注；需要修改时应修改生成脚本或另建人工复核记录。

`sources.lock.json` 固定来源与上游文件哈希；`bundle.json` 固定派生数据清单、输入白名单、准备脚本和环境依赖哈希。后续每次模型评测应引用这个数据版本和知识索引版本。

## 9. 下一步开发边界

下一步是工程骨架与真实解析 API 契约验证：读取完整语料清单，设计标准元素类型、后台任务及来源映射，再用有代表性的页面验证服务输出。**此时按少量页面验证 API 是控制成本，不是语料只准备了小规模。** 验证通过后对已就绪的完整数据批量入库，再建立固定 RAG 基线和 Agent 对照。

本轮没有接入模型、解析服务或数据库，也没有改变旧工程。MMDocRAG 属于设计中的后续可选外部困难基准，本版没有下载；当前两套完整公开数据与工程案例已覆盖本版开发范围。
