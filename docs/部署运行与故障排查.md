# 部署运行与故障排查

## 1. 运行边界

当前版本面向单机开发与演示，包含 FastAPI 后端、Vue 3 前端、PostgreSQL 业务库、Chroma 向量产物和持久化 BM25 索引。正式入库支持 Markdown/TXT、浏览器上传文件、其本地关联图片和受限 PDF；PDF 由 MinerU 异步解析后进入正式 worker。异常诊断 Agent 不属于本工程。

## 2. 环境准备

- Python 3.12；
- Node.js 20、pnpm 10；
- PostgreSQL 16；
- 阿里云百炼北京地域 Workspace ID 和 API Key（只有真实模型调用需要）；
- Windows PowerShell。

在项目根目录恢复后端依赖：

```powershell
uv sync --locked --extra test --extra index --python 3.12
Copy-Item .env.example .env
```

初始化独立数据库时，先以 PostgreSQL 管理员执行：

```powershell
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres -f scripts/bootstrap_database.sql
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres
```

在 `psql` 中使用 `\password multimodal_rag_app` 设置项目用户密码，然后把 DSN 只写入本地 `.env`，再执行版本化迁移：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli db-migrate
```

迁移具有校验和保护，不得直接修改已经执行过的 SQL 文件；新增结构应创建下一编号的迁移。

## 3. 配置原则

`.env` 不得提交 Git。个人开发可让对话、视觉、Embedding 和 Rerank 共用同一百炼 API Key；各模型仍通过独立配置项声明，方便后续拆分权限。只有同时满足 `MRAG_MODE=api`、`MRAG_API_ENABLED=true` 和具体命令的显式确认参数时，脚本才允许真实外部调用。

如果直连百炼失败但浏览器可以联网，可在 `.env` 设置：

```ini
MRAG_HTTPS_PROXY=http://127.0.0.1:7890
```

代理必须是可信的本机 HTTP 代理；不需要时留空。不要把带用户名、密码或查询参数的代理 URL 写入配置。

## 4. 启动与停止

终端一启动后端：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli serve
```

终端二启动前端：

```powershell
Set-Location frontend
corepack prepare pnpm@10.12.4 --activate
pnpm.cmd install
pnpm.cmd dev
```

访问地址：

- 前端：`http://127.0.0.1:5173/`
- API 文档：`http://127.0.0.1:8010/docs`
- 存活检查：`http://127.0.0.1:8010/health/live`

开发模式使用 `Ctrl+C` 停止对应终端。不要通过强制结束 PostgreSQL 进程来停止数据库，应使用 Windows 服务管理器或 `Stop-Service` 管理明确的 PostgreSQL 服务。

## 5. 发布前备份

业务元数据使用 PostgreSQL，索引产物在 `storage/` 或 `indexes/`。切换索引前至少备份数据库；需要完整恢复检索时，同时备份 active 索引目录和对应 manifest。

```powershell
pg_dump -h 127.0.0.1 -p 5432 -U multimodal_rag_app -d multimodal_rag -Fc -f multimodal_rag.backup
```

恢复属于覆盖性操作，应在新的空数据库中先验证，不要直接覆盖当前开发库。API 密钥无需进入备份。

## 6. 常见问题

### 前端显示“演示模式”或请求被拒绝

先访问 `/health/live`。若 8010 端口拒绝连接，启动后端；若后端正常而前端失败，确认 Vite 代理仍把 `/api` 和 `/health` 指向 `127.0.0.1:8010`。修改后端代码后需要重新启动没有热加载的服务。

### PostgreSQL 连接失败

执行 `psql --version` 确认客户端安装，再使用 `.env` 中相同的主机、端口、数据库和用户手工连接。重点检查 PostgreSQL 服务是否运行、密码是否正确、数据库与角色是否由 `bootstrap_database.sql` 创建。不要把 DSN 直接当作 PowerShell 命令执行。

### 百炼接口超时或只有某个模型无法连接

先运行依赖检查，不要连续重试真实评测。检查北京地域 Workspace ID、模型名称、API 开关和代理配置。VPN 不是必须关闭；应根据直连/代理验证结果选择稳定链路，并保持 `trust_env=false`，让代理完全由 `.env` 控制。

### Rerank 不可用

检索会标记为降级并保留 RRF 顺序，不会自动伪造重排结果。检查 Rerank URL 与普通 Chat URL 不同，并确认请求预算。恢复后使用普通联调问题验证，禁止借此重跑冻结 test。

### 审核队列返回 422

接口 `limit` 上限为 100。前端已经使用 `limit=100`；自定义客户端必须遵守 OpenAPI 中的分页约束。

### 新资料已审核但检索不到

“审核通过”不等于“已发布”。检查是否已经为处理版本构建索引、Chunk/Vector/BM25 是否一致，以及新索引是否经过显式激活。系统只读取唯一 active 索引。

### 文档需要更新或下线

更新同一知识库中的同名文件会产生新的内容版本，旧版本不会被覆盖。下线通过 `POST /api/v1/documents/{document_id}/retire` 完成，必须提交操作人、原因和确认标记；该操作只改变版本状态，不会立即删除当前 active 索引。随后使用 `build_mode=rebuild_without_retired` 构建并审核新索引，激活成功后检索范围才会移除该文档。完整流程见 `docs/6C_文档版本更新与下线流程.md`。

### 图片无法显示或 VLM 拒答

检查图片 Element 是否关联到命中 Chunk、原图是否仍位于白名单数据目录、文件哈希是否匹配。系统会拒绝目录穿越、缺失文件、类型不匹配和超限图片，这类拒答属于安全门禁而不是模型故障。

## 7. 验收命令

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest backend/tests -q
Set-Location frontend
pnpm.cmd build
```

浏览器端无模型验收使用 `scripts/verify_stage6b_web.py`，它只访问本地接口、切换页面和核对已存在的评测指标，不提交问答或重跑 test。

GitHub Actions 会运行不依赖本机私有语料和数据库的离线测试；`test_real_development_document_offline` 需要本地完整开发语料，因此标记为 `real_data`，只在开发机显式执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest backend/tests -m real_data -q
```
