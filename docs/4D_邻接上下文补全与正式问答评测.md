# 阶段4D：邻接上下文补全与正式问答评测

## 为什么改进

阶段3检索评测中，唯一未完整召回的问题需要同一章节内两个连续Chunk共同支撑。Rerank已把主Chunk排在第一位，但被长度上限切开的后半段没有进入Top 5。这个现象说明检索排序没有完全失效，问题出在生成阶段缺少同章节连续上下文。

## 最终设计

问答链路在Rerank之后增加轻量邻接补全：只对前三个命中Chunk，在同一`processing_version_id`和同一标题路径内读取前后各一个Chunk，按Chunk编号去重，并标记为`adjacent`。扩展结果只供Context Builder组装本轮Prompt，不写回向量库、不参与Recall@5等检索指标，也不会跨章节拼接。Context Builder继续执行12,000字符预算、来源编号和提示注入隔离。

真实索引验证中，Region Merge问题缺失的`chk_15e48d8c...`已通过该规则补入，补全后两个标准证据都进入模型上下文。

## 正式问答评测

评测集使用`retrieval_stage3_text_gold_v1.jsonl`，共11条，其中8条可回答、3条无答案或需要澄清。脚本只接受已经`approved`且`gold_eligible=true`的样本。答案中的`[n]`会被解析并映射到实际Chunk；送入上下文但模型没有引用的证据不计为“已使用”。

| 指标 | 结果 |
| --- | ---: |
| 成功样本 | 11 / 11 |
| 实际引用证据召回率 | 1.00 |
| 引用编号有效率 | 1.00 |
| 完整证据覆盖率 | 1.00 |
| 无答案/澄清题拒答率 | 1.00 |
| 最终有效逐题报告记录的外部API调用 | 33 |

首轮有1条Chat响应因供应商响应契约不完整失败，脚本使用`--only-failed`只重试该题，最终11条全部完成。最终有效逐题报告记录33次调用；若把第一次失败题已发生的3次Embedding、Rerank和Chat请求也计入，本次实际执行共发生36次外部请求。正式汇总位于`evals/results/stage4/qa_eval_summary.json`，逐题报告按索引版本保存在`evals/results/stage4-qa/<index_version_id>/`，网页评测页可读取并展示汇总指标。

## 指标边界

本阶段证明了标准证据是否被答案实际引用、引用编号是否合法，以及系统能否对限定范围内的无答案题拒答；它不直接证明开放式答案的每个表述都语义正确。后续需增加必要答案要点、数值和条件核验，对开放式答案使用固定评分标准与LLM初评，并人工复核争议样本。当前Gold集中Region Merge问题的“默认值”指代也偏宽泛，应在下一版问答评测集里改成明确参数名，不能通过模糊问题包装高分。
