# 阶段 6C：Git 发布候选检查清单

## 发布级别

本阶段建立独立 Git 仓库并形成 `v1.0.0-rc1` 本地候选版本。之所以不直接标记正式 `v1.0.0`，是因为项目所有者还需要确认：

1. GitHub 仓库是公开还是私有；
2. 项目自有代码采用何种许可证；
3. GitHub 仓库名称和简介；
4. 是否把完整历史设计文档全部公开，或只保留核心文档。

## 首次提交范围

纳入：后端与前端源码、数据库迁移、自动化测试、数据准备与评测脚本、可复现数据清单、人工审核 Gold、项目设计/验收文档和依赖锁文件。

排除：`.env`、虚拟环境、Node 依赖、原始与派生语料、图片/PDF、评测运行结果、数据库与索引产物、临时目录、本地 Agent 配置和构建缓存。

## 自动检查结果

- 后端测试：234 passed；
- Vue 类型检查及 Vite 生产构建：通过；
- 无模型浏览器端到端验收：通过；
- 公开化审计：未发现疑似真实凭证、Workspace ID、私钥、大文件或本机绝对路径；
- `.gitignore` 已覆盖密钥、数据、索引、评测结果与依赖目录；
- 第三方来源和数据许可边界已写入 `THIRD_PARTY_NOTICES.md`。

## 正式发布门禁

在创建远端仓库和正式 `v1.0.0` 前，必须完成：

- 选择项目代码许可证并新增根目录 `LICENSE`；
- 再次运行 `scripts/audit_public_release.py`；
- 检查 `git status` 为空且 `git remote -v` 指向正确仓库；
- 明确仓库可见性，公开仓库不得包含公司内部数据或个人密钥；
- 推送后从 GitHub 页面抽查 README、第三方声明与文件清单。
