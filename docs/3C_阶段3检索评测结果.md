# 阶段3C：累计索引正式文本检索评测

## 评测范围

评测对象是当前 active 累计索引 `idx_e3ee3ea70457a1e4bfe42b21d7e5584d7eca3532c900bb5e`，覆盖41个处理版本及669个Chunk。正式评测集为 `retrieval_stage3_text_gold_v1.jsonl`，包含8条已审核文本证据题和3条无答案/澄清题。2条尚待人工发布的视觉题及3条缺少第二来源文档的多文档题均未混入正式指标。

每条问题调用一次查询 Embedding，在本地执行 Dense、BM25 和 RRF；8条可回答题再调用一次 Rerank。Top 5结果用于计算 Recall@5、Precision@5和MRR。评测脚本会拒绝 `gold_eligible=false` 或未批准的候选样本，避免把待审核标注包装成正式成绩。

## 结果

本轮共调用19次API（11次Embedding、8次Rerank），全部完成且重排未降级：

| 范围 | Recall@5 | Precision@5 | MRR |
| --- | ---: | ---: | ---: |
| 8条文本证据题 | 0.9375 | 0.2000 | 1.0000 |

文本题中 `zh_configuration_d5da7a9e` 需要两个相邻Chunk，Top 5只召回第23号Chunk，未补入同章节的第24号Chunk，因此该题Recall为0.5；其余7题的正确证据均排在第1位。Precision@5为0.20，是因为多数题只标注1个正确Chunk而固定返回5条，并不表示首条排序错误。结果说明新增4个Chunk后检索质量未发生回归，同时明确暴露出邻接上下文补全尚未纳入评测链路。

3条无答案/澄清题均能检索到5条相似候选，这是检索器的正常行为，不计算Recall、Precision和MRR，也不能据此宣称系统已经拒答。下一阶段需要在问答链路中验证证据充分性判断、资料不足拒答和澄清行为。

逐题结果和汇总保存在 `evals/results/retrieval-stage3/idx_e3ee3ea70457a1e4bfe42b21d7e5584d7eca3532c900bb5e/`。该数据集是项目内部、与当前Chunk版本绑定的人工审核集，不冒充通用公开基准；后续重新切分时必须重新核对证据映射。
