# 阶段 6A：项目状态与最终评测收口

## 1. 本版本范围

本工程只交付“面向企业研发资料的多模态 RAG 知识库与可信问答平台”。核心目标是让 Markdown/TXT 技术资料及其关联图片经过可审计的入库和发布流程后，能够通过混合检索、文本模型和视觉模型生成带文字与图片引用的回答。异常诊断、LangGraph 诊断工作流和测试平台 Tool 调用属于另一个 Agent 项目，不计入本工程的竣工范围。

## 2. 已完成的产品闭环

### 2.1 版本化知识入库

系统从受控白名单读取 Markdown/TXT 文件，校验路径、格式、大小和内容哈希，解析为标题、正文、代码及图片等结构元素，再采用结构感知的分层递归策略生成 Chunk。文档版本、处理配置、元素、Chunk 和处理任务均持久化到 PostgreSQL；重复执行保持幂等。解析和切分结果必须经过人工质量审核，审核通过只代表具备建索引资格，不会自动上线。

### 2.2 索引构建与发布

Dense 向量由 Embedding 模型生成并存入 Chroma，关键词索引以 BM25 产物持久化到磁盘，索引版本和业务元数据保存到 PostgreSQL。构建真实向量前必须显式确认请求预算；激活前再次校验全部处理版本已审核、Chunk/Vector/BM25 数量一致且产物目录有效。新索引激活后，旧索引退役，系统始终只读取一个 active 版本。

### 2.3 混合检索与可信文本问答

查询先生成向量，在 Chroma 中执行 Dense 语义召回，同时从当前 active 的 BM25 产物执行关键词召回；两路结果通过 RRF 按名次融合，再由 Rerank 对候选证据进行精排。命中内容可按章节和 Token 预算补充相邻 Chunk。回答只能基于最终上下文生成，并返回文档、章节、行号和 Chunk 引用；证据不足时明确拒答或要求澄清。

### 2.4 图文联合问答

系统根据检索命中的 Chunk 反查关联图片 Element，经过安全路径、文件类型、大小和哈希校验后，结合文档标题、图片 Alt、文件名及邻近文本选择最多 3 张原图。确有看图需求时调用 VLM，普通问题继续使用文本模型；响应同时返回文字引用、图片引用和原图访问接口，便于人工复核。

### 2.5 Web 工作台

Vue 3 + TypeScript 前端已接入 FastAPI 后端，包含知识问答、图片证据展示、资料导入、质量审核、索引构建、显式激活和评测结果查看。评测页同时展示严格确定性指标与开发级 LLM Judge 指标，不隐藏较低结果。

## 3. 最终评测状态

### 3.1 文本检索与问答

文本 Gold 包含 8 条有答案问题和 3 条无答案/澄清问题。固定 Top 5 下 Recall@5 为 0.9375、Precision@5 为 0.20、MRR 为 1.00；实际引用证据召回、引用编号有效、完整证据覆盖和无答案拒答均为 1.00。两条歧义题经过人工核验后仅修订问题表达，并留存版本记录。该评测集规模较小，定位是工程回归而非通用基准。

## 4. 已知边界

- 正式入库 worker 当前支持 Markdown/TXT 及其中关联的本地图片；PDF、MinerU、OCR 和 VLM 解析已验证，但尚未并入正式版本化入库链路。
- 原始中文数据池有 1,109 份公开文档，当前 active 索引只使用经过审核的 69 个处理版本。
- 目前是单机开发部署，尚未建设企业统一身份认证、多租户权限、对象存储、高可用和分布式任务队列。
- 数据集与正式 Gold 规模仍有限，现有指标用于证明链路、版本与评测方法有效，不能外推为所有企业资料的总体准确率。

## 5. 正式竣工前的阻塞项

v1 核心功能已经闭环。竣工前只保留以下工程收口项：

1. 使用浏览器对问答、图片引用、资料导入、审核、建索引/激活门禁和评测展示做一次端到端回归，并保存验收记录；
2. 清理前端仍存在的演示占位交互或明确标记为只读，避免用户误以为已经接入；
3. 补充部署、环境初始化、备份恢复和常见故障排查文档；
4. 在公开仓库提交前执行密钥、绝对路径、大文件、许可和 Git 忽略规则检查；
5. 创建版本标签并形成 v1 验收清单。

PDF/OCR 正式入库、扩大人工 Gold、容器化/CI、权限系统与观测告警属于推荐增强项，不阻塞当前 v1 竣工；异常诊断 Agent 明确不在本工程中实现。
