# 0A：离线工程骨架——验收与学习指南

日期：2026-09-24。状态：已实现并通过本机验收。**这不是完整 RAG 应用，也不是模型效果评测。**

## 1. 本批交付了什么

工程现在可以独立启动 FastAPI，检查配置，通过文档编号预览开发侧 Markdown/TXT 的结构，并输出带原文定位的元素 JSON。应用依赖在 `.venv`，固定在 `uv.lock`；原数据环境 `.venv-data` 和 `requirements-data.lock.txt` 保持不变。没有读取旧项目密钥、连接旧数据库或修改旧项目。

| 层级 | 文件入口 | 这一层负责什么 |
| --- | --- | --- |
| 接口层 `api` | `backend/src/multimodal_rag/api/app.py` | 接收请求、校验编号、返回结果和安全错误、记录请求编号 |
| 应用层 `application` | `preview.py`、`dependencies.py` | 协调读取原文、解析和来源校验；区分配置检查与真正连通 |
| 核心层 `core` | `models.py`、`errors.py` | 定义文档、原文版本、元素、来源、任务及错误，不依赖 HTTP |
| 基础设施层 `infrastructure` | `settings.py`、`documents.py`、`text_parser.py`、`logging.py` | 读取环境、白名单和本地文件；执行最小结构解析和安全日志 |

一个请求的实际顺序是：**文档编号 → 开发白名单 → 路径与文件哈希检查 → 本地结构解析 → 逐元素原文回查 → JSON 返回**。API 和命令行复用这一条链路，没有两套业务逻辑。数据库、worker、最终切分、索引和模型适配器不在本批预建空实现。

## 2. 如何运行和查看

在 PowerShell 中执行以下命令，不需要先激活虚拟环境，也不需要配置密钥：

```powershell
# 在项目根目录执行

# 检查配置是否填写；不是数据库/API连通性测试
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli check-env

# 解析一份已准备的真实开发侧文档，保存预览 JSON
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli preview

# 启动后端（保持这个终端开启，Ctrl+C 停止）
.\.venv\Scripts\python.exe -X utf8 -m multimodal_rag.cli serve
```

默认地址 `http://127.0.0.1:8010/docs` 是接口调试页，**不是最终知识库前端**。Swagger 页面静态资源默认来自 CDN；断网时可直接通过 PowerShell 调用 API，或查看本地 OpenAPI JSON，不影响离线预览能力。

```powershell
Invoke-RestMethod http://127.0.0.1:8010/health/live
Invoke-RestMethod http://127.0.0.1:8010/api/v1/dependencies
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8010/api/v1/preview `
  -ContentType 'application/json' `
  -Body '{"document_id":"tidb85_b5ecd98ba8b7dd54"}'
```

默认演示文档是《在公有云上部署 TiDB 的最佳实践》，来自现有 `dev` 白名单，而非测试集答案。实际输出 **84 个元素：20 个标题、51 段正文、7 个代码块、2 个表格和4个图片引用**。命令行预览保存到 `evals/results/offline-preview/preview.json`；HTTP 预览本身不写文件、不创建索引。`persisted=false` 指没有进行业务持久化，命令行或验收脚本显式保存的 JSON 只是检查产物。

`GET /health/live` 返回200，只说明进程存活；`GET /health/ready` 在0A返回503，明确表示完整服务依赖未就绪，这是预期行为。`/api/v1/dependencies` 只报告配置是否填写，既不尝试数据库连接，也不调用模型。即使填写密钥，也只显示“适配器尚未实现”，不会假装连通。`check-env --real` 显式拒绝并返回非零退出码，真实检查留到0B。

需要自定义端口时，手动将 `.env.example` 复制成 `.env` 后修改 `MRAG_PORT`；**不要覆盖已有 `.env`**。系统环境变量优先于 `.env`。不填写任何配置也能离线启动，错误类型或未知配置会报错，不会静默忽略。`offline / mock / api` 是明确的模式标识；0A在任一模式下都只有真实本地解析，未提供模型 Mock 回答或 API 调用。

换电脑需先安装 Python 3.12 和 uv，在项目根目录执行 `uv sync --locked --extra test --python 3.12`；该安装步骤需要下载依赖，不属于离线运行。已经有 `.venv` 时可以直接执行上面的命令。若 uv 默认缓存不可用，可补充 `--cache-dir .uv-cache`。完整数据回归另需按原数据指南恢复 `.venv-data`，不能用应用环境替代。

## 3. 数据设计怎样理解

**文档**表示资料身份，**原文版本**由文档编号和内容哈希确定；同一份原文重复预览获得相同版本和元素编号，每次执行有不同任务编号。当前版本始终为 `draft`，任务为 `preview`；预览成功不代表知识已经发布。后续入库阶段再增加包含解析器、切分参数及索引配置的处理版本，不能只用原文哈希判断是否应重建索引。

**元素**是标题、正文、表格、代码或图片引用，还不是检索 Chunk。Markdown 使用语法解析器识别结构，代码围栏中的 `#` 不会误当标题，表格保留完整原始文本；跳过 YAML 文件头时保持原文行号。TXT 暂时只按空行形成段落，不猜测复杂标题。每个元素记录文档和版本、顺序、标题路径及原文起止行，`raw_text` 直接来自这些行，校验时重新对照，防止格式转换导致引用错位。

**来源定位**按资料类型划分：文本记录从1开始、两端包含的行号；PDF记录从1开始的物理页码，没有可靠坐标时仅标页级；独立图像记录图像引用和尺寸。区域框约定左上为原点、坐标归一化到0～1。PDF/图像目前只有数据契约及校验测试，并不表示已经实现 PDF 解析或图片理解。Markdown 图片元素的行号定位的是“原文中引用图片的位置”，不是图像内的区域。

图片引用不自动读取或下载，HTML和模板内容只保留为原文，不执行；图片模型描述单独预留字段且保持空值。图片与文字混排时多个元素可能引用同一段原文，因此元素数量不能视为相互独立的证据数量，后续切分需做去重。

## 4. 测试结果和真实边界

运行完整0A验收：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/verify_stage0a.py
```

| 验收项 | 实际结果 | 检查内容 |
| --- | --- | --- |
| 应用单元/接口测试 | 45/45通过，无跳过 | 类型与配置、原文回查、路径越界、测试集隔离、哈希不一致、大小上限、日志/错误脱敏、健康接口 |
| 原有数据回归 | 29/29通过，无跳过 | 继续使用原数据环境检查来源完整性、划分、证据关联和审核边界 |
| 实际HTTP启动 | 8项检查通过 | 独立子进程监听本机临时端口，测试健康、OpenAPI、预览及来源结果，结束后停止服务 |
| 模型调用/数据库连接 | 0次 / 未连接 | 不产生模型调用费用，不涉及数据库数据变更 |

报告入口：[0A验收报告](../evals/results/stage0a/report.html)。每次执行产生独立时间戳目录，保存JUnit、测试日志、服务日志、真实文档预览、数据版本、依赖版本及源码哈希；顶层入口指向最近一次结果。测试失败会返回非零退出码，不能将未执行、跳过或缺失数据当成通过。

开发时首轮测试发现Windows异步事件循环会使用本机回环socket作为内部通信，已将离线网络守卫调整为允许回环、拒绝外部连接；另确认初选文档没有表格，最终选择同时具备正文、代码、表格和图片引用的开发文档。当前测试没有衡量OCR质量、视觉事实正确率、检索召回率或Agent成功率。

## 5. 推荐学习顺序与下一批

先运行 `preview`，看一个标题元素和一个表格元素如何对应原文件行号；再读 `application/preview.py` 理解整体过程；接着读 `core/models.py` 理解文档、版本、元素的区别；最后查看白名单读取、解析器和对应测试。这样先掌握一条完整路径，再了解边界处理，不必先记住所有字段。
