## 3. 第一批 0A：现在应先做什么

### 工程骨架与配置

建立独立应用环境与锁文件，保留现有 `.venv-data` 和数据脚本。后端保持四层职责，不预建大量空类、插件体系或通用框架：

```text
backend/
  src/multimodal_rag/
    api/                    # HTTP 路由及对外输入输出
    application/            # 用例协调；不把业务写进路由
    core/                   # 文档、元素、来源、任务等核心数据结构
    infrastructure/         # 配置、日志、存储和外部服务适配
  tests/                    # 单元与接口测试
scripts/                    # 环境检查、启动与验证入口
evals/configs/              # 可复现的非敏感测试配置
evals/results/              # 真实运行报告，不提交仓库
```

配置统一由 `.env` 加类型校验读取，`.env.example` 只包含占位符和说明。区分离线、Mock 和真实服务模式：缺少密钥时不得偷偷切换到假结果；离线启动只证明应用存活，依赖未配置必须明确显示。日志带请求编号，密钥、连接口令和完整认证头不输出。

先实现应用存活检查和显式依赖检查。普通存活检查不调用付费模型；数据库或供应商检查采用单独命令，真实 API 检查必须显式开启。测试从第一批开始输出 JUnit、日志及简明汇总，不等功能全部完成才补测。

### 统一数据结构与最小离线链路

先确定文档、文档版本、元素、来源定位和入库任务五类核心结构。元素至少能区分正文、标题、表格和图像，记录原文、所属文档版本、阅读顺序及可用的来源位置。MD/TXT 使用标题和行号；PDF 使用物理页码及可选区域框；独立图像使用图像引用及尺寸。没有坐标时保留空值并标记定位精度，不伪造框。

在已准备的开发侧 MD 中选一份原文，完成“白名单读取 → 标题/正文/表格/图片引用的最小元素输出 → 来源校验”的离线演示。只证明工程模块与接口能连接起来，不在这一批实现完整解析器、向量索引或最终切分。Mock 外部响应是程序测试夹具，不能作为真实解析成绩。

**0A 验收重点：**应用可启动、配置校验有效、健康接口可测试、元素可序列化、来源能够回到原文件、非法路径被拒绝、未配置依赖不会伪装成功、已有数据检查没有回归。第一批无需用户提供模型密钥或安装新服务。

## 4. 第二批 0B：环境与 API 接口验证

数据库继续采用 PostgreSQL，但先提供独立数据库与角色初始化脚本，由用户安装或确认环境后执行；不默认借用旧工程的数据库和用户。最初只迁移文档、版本、元素和入库任务相关表，会话与图检查点在后续使用时再加入。

外部服务按职责实现独立适配器：文档解析、对话、视觉、Embedding、Rerank。依次核验认证、地域与地址、返回结构、异常处理及用量字段。Embedding 检查实际维度与空文本处理；Rerank 检查分数、结果编号与原候选对应；视觉接口检查是否确实收到原图；解析接口检查任务状态、结果获取、页码、内容列表和图片资源。不能只看到 HTTP 200 就认定接口满足设计。

先做 Mock 的超时、限流、无效响应、有限重试和凭证脱敏测试，再由用户确认服务和调用预算后发起最小真实请求。具体模型版本与价格在实施时查询官方资料；没有价格信息时只记录调用量，不编造费用。

**需要用户确认：**解析服务是否可用及凭证、模型服务/地域、单批调用上限或费用预算、独立 PostgreSQL 环境。凭证由用户填入本地配置，不在聊天中索要明文。未经确认不全量提交文档，也不自动安装数据库。

## 5. 第三批 0C：先验证解析与证据，再开展批量入库

### 固定一组代表性验证材料

只从已有开发侧资料中选取约 20 个页面，覆盖中文原生 PDF、中文扫描/复杂版面、表格、架构图/操作截图及英文图文页面，每类约 4 页；类别重叠时明确主分类。另取约 6 份 MD/TXT 做本地解析检查。优先保留单页和连续页组合，以检查图文关联与跨页情况。材料来自完整已备语料，不重新下载小数据集；小批次只是控制 API 验证成本。

固定选择清单、哈希和来源映射，不根据模型回答临时更换“容易成功”的样本。测试侧资料和参考答案不用于调参。来源于完整文档的页片段必须记录局部页码到原文页码的映射，不能把切出的第1页误当成原文件第1页。

### 分开验证解析和视觉理解

MD/TXT 优先本地结构解析，不做无意义 OCR。PDF/扫描页验证解析服务能否保留正文、表格行列、图像引用、阅读顺序和页码；结构化输出统一到核心元素模型，原始供应商响应单独保存。图像路径必须关联到原文件或页图，并受本地资源范围约束。

对确实需要理解的图表再调用视觉模型，分别保存“原始证据”和“模型描述”。用少量已核对问题检查是否读对数值、单位、箭头关系和版本信息，并检查不可读时是否承认不确定。图像描述可作为检索文本，但不自动当作真实事实。缺坐标时先提供页级定位，不通过猜测坐标填满 Schema。

### 测试报告怎样呈现

本阶段只记录与当前能力对应的结果，不提前报告 RAG Recall 或 Agent 成功率：

| 检查项 | 记录内容 |
| --- | --- |
| 解析完成情况 | 提交、成功、失败的文件/页数，失败阶段及原因 |
| 来源正确性 | 页码、文档版本、图像引用、可用坐标是否合法并可回查 |
| 正文与表格 | 有参考标注时报告 CER 或表格关键值匹配；无标注时记录逐样例复核，不编总准确率 |
| 图像理解 | 预先确认的答案要点、数值和单位是否符合原图；模型补写的无证据事实 |
| 调用与运行 | 服务/模型标识、耗时、重试次数、Token或页数用量、缓存状态 |

对照材料采用原文/原图与输出并排的静态报告即可，本阶段不先开发完整标注平台。报告既列成功也列失败；失败归因为解析缺失、错序、表格错位、图文错配、视觉误读或接口异常。

## 6. 标注审核与正式评分的边界

工程开发不必等待全部 180 条候选审核结束，但正式中文问答质量评分必须使用审核后的固定子集。用户可随开发从开发集审核约 20 条代表问题，覆盖文字、参数、表格、图像、多证据、拒答/澄清；助手协助解释证据，审批仍由实际审核者完成。

参考答案、证据编号和正确文档编号只进入评分端，不输入被测 Agent，也不作为检索过滤的隐藏条件。中文章节/图像指标、英文页面指标分别记录；不能因格式副本多而重复计算证据命中。人工审核状态、数据检查通过和模型效果通过是三种不同状态。

## 7. 阶段验收与后续路线

阶段0结束时交付可启动工程、依赖锁、数据库初始化/迁移说明、统一接口与元素结构、离线测试报告、真实 API 验证报告、代表资料解析对照以及已知问题清单。运行记录包含代码提交号或源码哈希、数据版本、配置/服务版本；未建立 Git 时不伪造提交号。

进入阶段1至少需要：数据库环境可用，核心解析输出能够适配，来源映射无未解释错误，所选模型接口可调用，调用预算明确。页面坐标等非必需能力不满足时，可经确认降级为页级定位；关键原文或表格持续缺失则先处理失败，不以增加 Agent 编排掩盖入库问题。
