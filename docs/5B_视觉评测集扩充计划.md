# 阶段5B：视觉评测集扩充

> 最终状态（2026-09-25）：30 条候选已全部经过人工逐图审核并发布为 Visual Gold v2.4（20 dev / 10 test）。方案冻结后已完成一次 test，视觉证据组召回与图片引用有效率均为 1.00，严格确定性通过率为 0.70，开发级 LLM Judge 语义通过率为 1.00。最终测试后未调整流程或重跑 test。完整口径见 [阶段6A收口说明](6A_项目状态与最终评测收口.md)。以下内容保留阶段5B的开发与迭代过程。

## 目标与边界

将现有2条正式视觉Gold扩展为30条候选，固定为20条开发集和10条测试集。候选覆盖产品界面截图、监控曲线、架构或流程图、表格截图、终端截图和热力图。开发集用于定位检索、选图与提示词问题；测试集只用于方案固定后的最终评测，避免反复调参造成数据泄漏。

这里的dev/test划分约束的是**问题、参考答案和评测结果**，不是把测试题对应的公开技术文档排除出知识库。RAG评测的前提是系统能够检索完整知识语料，因此30篇来源文档都进入入库白名单；清单额外保留`source_evaluation_split`记录原始分区，但不会把问题或答案写入知识库。

候选问题和答案来自公开TiDB中文文档及原始图片，图片、文档和哈希已在生成时校验。自动生成只能形成候选，不能自动升级为Gold。每条都需要人工实际查看原图，核对问题、答案、数值、单位和图像证据，并登记可替代图片或应排除图片。

## 实施顺序

```text
30条视觉候选与原图完整性校验
  → 30篇来源文档的独立入库白名单
  → 文档解析、结构切分与人工质量审核
  → 构建并激活包含视觉文档的新索引
  → 将问题映射到Chunk和图片Element
  → 人工逐图审核并发布visual_gold_v2
  → 先运行20条dev，再一次性运行10条test
```

该顺序把“资料是否已入库”“检索是否找到正确章节”“系统是否选择正确图片”和“VLM是否正确回答”分开验证。索引构建前仍需显式确认Embedding预算，人工审核前不会写入正式Gold，正式评测前不会调用VLM。

## 首轮dev评测与迭代

30条候选经逐图人工审核后已发布为视觉Gold v2（20 dev / 10 test）。首轮只运行20条dev，共发生59次外部请求；test没有运行。首轮视觉链路完成率0.95，但正式通过率仅0.25，视觉证据组召回0.65、被回答实际引用的证据组召回0.55、必要要点覆盖0.4292，并出现0.05的排除图片误选率。

逐题分析表明，主要问题不是VLM不可用，而是文本检索命中相关领域后，无法稳定选中题目明确或隐含指向的原图；同时复合答案要点使用严格字符串匹配，容易把标点、引号和自然语言插入词误判为缺失。为此增加了“问题中的精确文档标题约束→图片Alt/文件名/邻近Chunk相关性排序→强唯一标签只选一图”的选图策略，并把复合UI事实调整为原子要点或等价表达组。只在dev上执行的无模型选图检查中，三条问题需要补充图片标签才能消除同文档多图歧义；加入待审核修订后，20条dev的目标图片证据组召回达到1.00，排除图片误选为0，test仍未访问。

三条待确认问题修订保存在`evals/datasets/qa_stage5_visual_question_revisions_v2.jsonl`。修订获人工确认后才能生成Gold v2.1并重新运行dev；只有dev方案冻结后，才允许一次性运行10条test。
