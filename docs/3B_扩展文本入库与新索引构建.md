## 多文档索引设计

一个统一索引需要覆盖40个处理版本，不能把多个文档伪装成一个文档。`load_chunks_for_processing_versions` 和 `build_real_indexes_for_processing_versions` 接收完整的处理版本编号集合，按集合加载 Chunk；索引清单保存 `processing_version_ids` 全量来源。为兼容现有 `index_versions` 表，表中的 `processing_version_id` 仅作为可回溯的首个处理版本锚点，实际范围以清单中的完整集合为准。

构建顺序固定为：读取665个 Chunk → 每批10条调用一次 `text-embedding-v4` → 写入同一版本的 Chroma → 在本地生成 BM25 索引 → 校验 Chunk、向量和关键词索引数量一致 → 生成 `draft` 索引产物。本批已实际完成67次 Embedding 请求，得到665个1024维向量；Chroma、BM25和数据库记录均为665条，产物目录完整。BM25不调用外部服务。完成后仍需人工审核，不能自动激活。
