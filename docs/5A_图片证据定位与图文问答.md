# 阶段5A：图片证据定位与图文联合问答

## 实现链路

```text
用户问题
  → Dense + BM25 + RRF + Rerank
  → 同章节邻接文本补全
  → 从候选Chunk的element_ids反查图片Element
  → 校验活动知识版本、路径边界、格式签名、大小和SHA256
  → 按Chunk多样性选择最多3张原图
  → 有明确看图意图时调用VLM，否则沿用文本Chat
  → 返回文字引用、图片引用和可在网页复核的原图
```

客户端不能提交任意本地图片路径。图片必须来自当前检索Chunk包含的Element；外部URL、目录穿越、缺失文件、非法格式、错误签名、超出大小预算和读取后哈希变化都会被拒绝。网页读取原图时使用活动图片Element编号，后端再次校验该元素属于当前已激活处理版本，不直接暴露任意文件读取接口。

## 候选选择迭代

第一版直接取排序靠前的两张图。QPS题所在Chunk包含默认配置和调整后两张截图，因此两张图都能送入VLM；TiCDC题中，排名靠前的“组件介绍”Chunk包含多张局部图，挤掉了真正包含Owner、node1和下游系统的总览图，结果只能回答3个下游系统，无法确认node1。

仅把上限提高到3张仍不稳定，因为同一Chunk可以继续占满名额。最终改为按Chunk进行多样化选择：先从每个检索Chunk各取一张，再补同一Chunk的第二张。该策略不借助Gold图片编号，重新执行后成功选到另一张能够完整支撑结论的TiCDC架构图，VLM回答了Owner位于node1以及MySQL、TiDB、Kafka三个下游系统。

## 正式视觉 Gold 与评测结果

两条开发候选均由人工实际查看原图后发布为`retrieval_stage5_visual_gold_v1.jsonl`。QPS题明确限定默认配置截图，并把调整后截图登记为排除证据；TiCDC题把两张均可独立支撑答案的架构图登记为可替代证据组。正式评测入口只接受`approved + gold_eligible + human_released_gold_v1`的样本，并同时检查答案要点、证据组命中、排除图片误选和图片引用有效性。

## 评测边界

当前成绩使用了人工发布的正式视觉 Gold，因此可以表述为“2条正式视觉样本全部通过”。但样本规模仅为2，统计意义很弱，只能用于图文链路验收，不能表述为平台整体视觉准确率。后续需要扩充图表、架构图、截图、扫描页和无答案图片等不同类型的Gold样本，才能形成有代表性的质量指标。

正式评测命令（每题最多调用Embedding、Rerank和Vision各一次）：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\run_stage5_visual_qa_eval.py --confirm-live
```

## 网页能力

统一问答入口`POST /api/v1/qa/multimodal`会自动判断是否需要看图；文本问题仍返回`answer_mode=text`，图像问题返回`answer_mode=vision`或安全拒答`visual_refusal`。Vue工作台已切换到该入口，并通过`GET /api/v1/visual-elements/{element_id}/content`展示本轮实际送给VLM的原图及来源行号。
